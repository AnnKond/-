# DNS
**Domain Name System** · раздел: [Сетевые сервисы](../README.md)

## Суть
DNS превращает имена вроде www.example.com в IP-адреса, по которым компьютеры находят друг друга. Ни один сервер не знает всех имён: система — это иерархия серверов, а ответы кэшируются по пути, так что большинству запросов не приходится идти далеко.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Уровень | Прикладной (7) |
| Порт | 53, UDP (TCP для больших) |
| Превращает | Имена в IP-адреса |
| Иерархия | Корень → TLD → авторитетный |
| Кэширование | На время TTL записи |
| Описан в | RFC 1034, RFC 1035 |

## Как работает (по шагам)
1. Спросить резолвер — ноутбук передаёт вопрос
2. Корневой сервер — указывает путь к .com
3. Сервер TLD .com — указывает путь к example.com
4. Авторитетный сервер — даёт настоящий ответ
5. Ответ и кэш — ноутбук получает адрес и запоминает на час

## Основные термины
- **Доменное имя** — Человекочитаемое имя узла.
- **Резолвер** — Сервер, выполняющий поиск за клиента (например, 8.8.8.8).
- **Корневой сервер** — Вершина иерархии DNS.
- **TLD** — Домен верхнего уровня: .com, .ru.
- **Авторитетный сервер** — Сервер, хранящий записи конкретного домена.
- **Запись A / AAAA** — Сопоставление имени с IPv4 / IPv6 адресом.
- **Запись MX** — Почтовый сервер домена.
- **TTL записи** — Сколько секунд ответ можно хранить в кэше.
