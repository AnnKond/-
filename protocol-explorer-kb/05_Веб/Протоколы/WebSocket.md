# WebSocket
**Протокол WebSocket** · раздел: [Веб](../README.md)

## Суть
WebSocket держит одно открытое соединение между страницей и сервером, так что любая сторона может отправить сообщение в любой момент: чаты, спортивные счета, игры, совместные документы. Он начинается как обычный HTTP-запрос с просьбой об обновлении (Upgrade); после этого сообщения идут маленькими кадрами с заголовком всего в несколько байт.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Уровень | Прикладной (7) |
| Порты | 80 (ws://), 443 (wss://) |
| Начало | HTTP-запрос (Upgrade) |
| Затем | Кадры в обе стороны в любое время |
| Заголовок кадра | 2–14 байт |
| Описан в | RFC 6455 |

## Как работает (по шагам)
1. TCP-соединение — как для HTTP
2. Просьба об обновлении — HTTP-запрос с Upgrade: websocket
3. Смена протокола — ответ 101, дальше WebSocket
4. Живые обновления — маленькие кадры с любой стороны
5. Поддержание — ping и pong
6. Закрытие — по кадру close в каждую сторону

## Основные термины
- **Upgrade** — HTTP-заголовок с просьбой сменить протокол.
- **101 Switching Protocols** — Ответ сервера о переходе на WebSocket.
- **Кадр (frame)** — Единица сообщения WebSocket.
- **ping / pong** — Кадры проверки, что соединение живо.
- **Полнодуплексная связь** — Обе стороны передают одновременно.
