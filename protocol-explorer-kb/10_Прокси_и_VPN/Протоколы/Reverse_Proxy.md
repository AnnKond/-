# Обратный прокси
**Обратный прокси и TLS (SSL) offloading** · раздел: [Прокси и VPN](../README.md)

## Суть
Обратный прокси стоит перед серверами сайта: посетители подключаются к нему, а он передаёт запросы серверу приложения. Он может распределять нагрузку, хранить копии страниц и отражать атаки. Часто он же выполняет работу TLS — расшифровывает HTTPS на входе, и серверы за ним общаются обычным HTTP. Это и есть SSL (TLS) offloading.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Уровень | Прикладной (7) |
| Посетители видят | Прокси, а не приложение |
| TLS заканчивается | На прокси (offloading) |
| Внутри | Обычный HTTP (или снова TLS) |
| Добавляет | X-Forwarded-For, X-Forwarded-Proto |
| Примеры | nginx, HAProxy, облачные балансировщики |

## Как работает (по шагам)
1. Парадная дверь — сертификат хранится у прокси
2. TLS заканчивается здесь — прокси выполняет работу TLS
3. Открытым текстом — передано серверу приложения
4. Приложение отвечает — тоже обычным HTTP
5. Снова зашифровано — посетитель получает обычный HTTPS-ответ
6. Три варианта — offload, повторное шифрование или сквозная передача

## Основные термины
- **Обратный (reverse) прокси** — Посредник на стороне сервера.
- **TLS offloading** — Расшифровка HTTPS на прокси.
- **Балансировка нагрузки** — Распределение запросов между серверами.
- **X-Forwarded-For** — Заголовок с настоящим IP посетителя.
- **nginx / HAProxy** — Популярные обратные прокси.
