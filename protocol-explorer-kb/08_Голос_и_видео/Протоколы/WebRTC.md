# WebRTC
**Web Real-Time Communication** · раздел: [Голос и видео](../README.md)

## Суть
WebRTC позволяет двум браузерам созваниваться: звук, видео и данные идут напрямую между ними, а не через сервер. Сервер только знакомит их: они обмениваются описаниями (сигнализация), находят путь через домашние роутеры с помощью ICE и STUN, шифруются DTLS и передают медиа по UDP как SRTP.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Уровень | Прикладной (7) |
| Медиа | UDP (SRTP) |
| Настройка | SDP, ICE, STUN, DTLS |
| Шифрование | Всегда включено |
| Работает | Во всех основных браузерах |
| Описан в | W3C; RFC 8825 и др. |

## Как работает (по шагам)
1. Подключиться к звонку — через сигнальный сервер
2. Публичный адрес? — спросить STUN-сервер
3. Предложение (offer) — SDP-описание через сервер
4. Ответ (answer) — браузер собеседника отвечает
5. Пробиться — проверки напрямую друг к другу (ICE)
6. DTLS-рукопожатие — ключи для медиа
7. Медиа идут — звук и видео напрямую
8. Точка — точка, а если не получилось — через TURN

## Основные термины
- **Сигнализация** — Обмен описаниями через сервер перед звонком.
- **SDP** — Текстовое описание медиа: кодеки, адреса.
- **ICE** — Поиск рабочего пути между участниками.
- **STUN** — Сервер, сообщающий устройству его публичный адрес.
- **TURN** — Сервер-ретранслятор, если прямой путь невозможен.
- **DTLS** — TLS поверх UDP.
- **SRTP** — Зашифрованный RTP для медиа.
