# TLS/SSL
**Transport Layer Security** · раздел: [Безопасность](../README.md)

## Суть
TLS создаёт защищённый канал поверх TCP. Он доказывает подлинность сервера сертификатом, согласует свежие ключи, затем шифрует и проверяет всё передаваемое. Внутри TLS работают HTTPS, защищённая почта и многие другие протоколы. SSL — название его предшественника.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Где | Между TCP и приложением |
| Уровень OSI | Часто относят к 6 |
| Актуальная версия | TLS 1.3 (RFC 8446) |
| Устарели | SSL 2 и 3, TLS 1.0 и 1.1 |
| Доказывает | Подлинность сервера (сертификат) |
| Порт | Порт приложения (443, 993 …) |

## Как работает (по шагам)
1. Client Hello — всё, что умеет браузер
2. Server Hello — выбор сделан, ключи вычислены
3. Сертификат — кто такой сервер, с доказательством
4. Finished — один круговой обмен, затем данные
5. Зашифрованные данные — записи, теги и билеты
6. Закрытие — close_notify, затем TCP

## Основные термины
- **Client Hello / Server Hello** — Первые сообщения рукопожатия.
- **Сертификат** — Связывает открытый ключ с доменом; подписан CA.
- **Цепочка доверия** — Сертификат → промежуточный CA → корневой CA.
- **Обмен ключами (ECDHE)** — Получение общего секрета без его передачи.
- **Симметричное шифрование** — Шифрование данных общим ключом (AES, ChaCha20).
- **SNI** — Имя сайта в Client Hello.
- **Сессионный билет** — Позволяет быстро возобновить соединение.
