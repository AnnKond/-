# DNSSEC
**DNS Security Extensions** · раздел: [Безопасность](../README.md)

## Суть
Обычные DNS-ответы можно подделать: кто ответил первым или стоит посередине, может прислать ложный адрес. DNSSEC позволяет резолверу проверить, что ответ действительно от владельца домена. Каждый набор записей подписан; ключ каждой зоны заверен родительской зоной — вплоть до корня, чей ключ встроен в резолверы. DNSSEC доказывает подлинность, но не скрывает запросы.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Уровень | Прикладной (7) |
| Новые записи | RRSIG, DNSKEY, DS |
| Проверяет | Резолвер |
| Якорь доверия | Ключ корня (встроен) |
| Скрывает запросы | Нет (это делает DoH) |
| Описан в | RFC 4033, 4034, 4035 |

## Как работает (по шагам)
1. Вопрос как обычно — запрос ноутбука не меняется
2. Подписанный ответ — RRSIG вместе с A-записью
3. Ключи зоны — записи DNSKEY, тоже подписаны
4. Заверено .com — DS-запись родителя
5. До корня — там цепочка заканчивается
6. Проверенный ответ — с флагом AD

## Основные термины
- **RRSIG** — Подпись набора DNS-записей.
- **DNSKEY** — Открытый ключ зоны.
- **DS** — Отпечаток ключа дочерней зоны у родителя.
- **Якорь доверия** — Заранее известный ключ корневой зоны.
- **Флаг AD** — Отметка «ответ проверен».
- **Цепочка доверия** — Последовательность подписей от корня до домена.
