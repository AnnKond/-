# TCP
**Transmission Control Protocol** · раздел: [Транспортный уровень (L4)](../README.md)

## Суть
TCP превращает доставку пакетов «по возможности» в надёжный упорядоченный поток байтов. Он нумерует каждый байт, подтверждает полученное, повторно отправляет потерянное и регулирует скорость отправителя, чтобы не перегрузить ни получателя, ни сеть.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Уровень | Транспортный (4) |
| Соединение | Тройное рукопожатие |
| Надёжность | Порядковые номера + ACK |
| Восстановление | Повторная передача |
| Заголовок | 20–60 байт |
| Описан в | RFC 9293 |

## Как работает (по шагам)
1. Открыть соединение — тройное рукопожатие SYN, SYN-ACK, ACK
2. Отправить данные — каждый байт пронумерован
3. Два сегмента назад — один из них потерян
4. Пробел замечен — дублирующий ACK с SACK
5. Повторить пропуск — только недостающие байты
6. Закрыть соединение — каждая сторона прощается (FIN)

## Основные термины
- **Тройное рукопожатие** — SYN → SYN-ACK → ACK — установка соединения.
- **Порядковый номер (Seq)** — Номер первого байта сегмента.
- **ACK** — Подтверждение полученных данных.
- **SACK** — Выборочное подтверждение — какие куски уже получены.
- **Повторная передача** — Отправка потерянных данных заново.
- **Управление перегрузкой** — Регулировка скорости отправки.
- **FIN** — Флаг завершения соединения.
