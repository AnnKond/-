# QUIC / HTTP/3
**HTTP/3 поверх QUIC** · раздел: [Транспортный уровень (L4)](../README.md)

## Суть
QUIC — новый транспорт поверх UDP со встроенным TLS 1.3. Первые пакеты выполняют транспортное и криптографическое рукопожатие одновременно, поэтому запрос страницы уходит уже через один круговой обмен. QUIC несёт много потоков сразу, так что один потерянный пакет не тормозит остальные, и переживает смену сети. HTTP/3 — это HTTP поверх QUIC.

## Ключевые факты
| Параметр | Значение |
|----------|----------|
| Уровень | Транспортный (4) |
| Работает поверх | UDP, порт 443 |
| Шифрование | TLS 1.3, всегда |
| Рукопожатие | 1 RTT (0 при повторном визите) |
| Потоки | Много, независимые |
| Описан в | RFC 9000, RFC 9114 |

## Как работает (по шагам)
1. Выбор HTTP/3 — прошлый визит сообщил, что сервер умеет
2. Initial-пакеты — Client Hello сразу
3. Server Hello — затем сертификат, уже зашифрован
4. Finished + GET — запрос через один RTT
5. Ответ — в своём потоке
6. Новая сеть — соединение узнаётся по ID, а не по адресу

## Основные термины
- **QUIC** — Транспорт поверх UDP со встроенным шифрованием.
- **HTTP/3** — Версия HTTP, работающая поверх QUIC.
- **Поток (stream)** — Независимый канал внутри одного соединения.
- **0-RTT** — Отправка данных сразу при повторном подключении.
- **Connection ID** — Идентификатор соединения, позволяющий сменить сеть без разрыва.
- **Блокировка начала очереди** — Проблема TCP, когда одна потеря задерживает всё; QUIC её устраняет.
